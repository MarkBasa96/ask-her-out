## Decisions worth knowing

- **Mark's page stays byte-for-byte the same in behaviour.** The loader only runs with `/p/<slug>`, `?p=<slug>` or `?preview=1`. With none of them there's no `await`, no Supabase call, and the same Formspree flow. The only visible change to his page is the new logo (which he asked for).
- **No extra `<span>`s in his HTML.** The first try wrapped "love" and "boyfriend" in spans, but the Yes button and badge are flex containers with `gap`, which added space around them. The custom wording is now set with JavaScript on builder pages only, and his page was pixel-compared against the previous version (identical).
- **Pronouns.** His page says "he". Builder pages use the creator's **name** instead ("Jamie's still crazy about you"), because "they" needs different verbs. Role (boyfriend/girlfriend/partner) only changes "your man"/"your girl"/the name and the badge.
- **Answers store `starts_at` (UTC)** plus the day, time and timezone they picked. The dashboard shows the time in *their* timezone and builds Google Calendar/.ics links from real UTC stamps that keep the `Z`.
- **The anon role can't read `owner_id`** (column grants), and can't read answers or reports at all.
- **Hiding is admin-only**, enforced by a trigger: owners can't hide or unhide, even their own page. Admins are listed by email in `public.admins`, which has RLS on and no policies, so it can't be read or changed through the API.
- **The date page talks to Supabase with plain `fetch`** (PostgREST), so it doesn't load supabase-js. The builder and dashboard load supabase-js 2 from jsDelivr (`dist/umd/supabase.js`; there's no `.min.js` in current versions).
- **Photos are shrunk in the browser** (longest side 1200px, JPEG), which keeps them under 2 MB and strips location data.
- **Live preview** is the real `ask-her-out.html?preview=1` in an iframe. It reads the draft from `localStorage['dp-preview']`, loads no music, and never saves answers.

## How it was tested

The cloud sandbox can't reach `*.supabase.co`, jsDelivr or YouTube, so:

- **Database rules** were tested for real on the new project with a SQL block that switches roles (`anon`, owner A, other user B, admin), then raises an exception so everything rolls back. 25 checks passed: 6th page blocked, 11th answer in an hour blocked, anon can't read `owner_id`/answers/reports, B can't read, change or delete A's things, B can't upload into A's photo folder, owner can only change `seen_at` on answers, only the admin can hide/unhide, hidden pages are invisible to visitors and can't be answered. The project was confirmed empty afterwards.
- **Pages** were tested in headless Chromium at 390×844 and 1280×800 behind a local server that copies `vercel.json`, with Supabase, Formspree and the CDN mocked by Playwright:
  - Mark's page: same text, same headline HTML, same ticket and Google Calendar link (`ctz=Asia/Manila`), only Formspree called, and a pixel-identical screenshot of `main` against the previous commit.
  - A builder page answered from `America/New_York`: 8:30 PM stayed 8:30 PM, `starts_at` was `00:30Z` the next day, `ctz=America/New_York`, and it POSTed to `answers` with no Formspree call. Report, unknown slug, `?p=`, no photo, custom cat lines and preview mode were checked too.
  - Builder and dashboard with a mocked signed-in session: magic-link request, auto slug, taken slug, photo shrink + upload into the user's folder, insert/update bodies, the 5-page limit, edit mode, answers marked seen, and the Admin tab hide button. No horizontal scroll at phone width.
- **Music** was tested with a fake YouTube IFrame API that blocks sound until a real user gesture, on Mark's page and on builder pages (with and without a song): starts muted → first tap unmutes → the mute button mutes and stays muted through other taps → unmute → loops when the song ends. Real YouTube can't be reached from the sandbox, so it's worth one listen on a phone after it's live.
- **Vercel**: the branch's preview deployment built, and `/p/<slug>` and `/p/Pics/...` were served through the rewrites.
